# Column on Oversized CIDH Shaft — Design Spec

Date: 2026-10-18 · Status: draft for review · Author: Claude (from the user's request; the user skipped brainstorming)

## 1. Intent

A new, self-contained **"Column on Shaft"** tab. The engineer pastes CSiBridge frame-force output
straight from the clipboard. The tab then:

1. groups the rows by frame element (each frame = one column or one shaft of a bent),
2. reduces the biaxial output to resultants that the circular engine can design for,
3. designs the minimum longitudinal and transverse reinforcement for every column with the
   **existing** circular AASHTO LRFD engine (`circ_engine` + `calc_engine.do_shear/do_torsion`),
4. runs seismic capacity design: plastic moment from moment-curvature, overstrength moment and
   plastic shear, column shear capacity, and the shaft's flexure and shear under the overstrength
   actions applied at the top of the shaft,
5. computes the **in-ground shaft moment and shear** (the moment increase below the top of shaft) from a
   p-y beam-column analysis of column + shaft on layered soil, as a function of shaft stiffness and the
   soil strata (ported from the seismic app's `pile_solver`/`soil`),
6. optionally (a user toggle, off by default) checks **column slenderness** per AASHTO §5.6.4.3 and magnifies
   the factored moments per Art. 4.5.3.2.2b before the strength design,
7. lets the engineer **override** the reinforcement (for example to satisfy displacement checks done
   in the separate seismic app), then re-checks everything with the override.

## 2. Goals / non-goals / anti-goals

**Goals**
- Paste-in of CSiBridge "Element Forces - Frames" tables, any units CSiBridge prints, with or without
  the `TABLE:` title line and units row.
- Circular column **and** circular shaft only (user, 2026-10-18).
- Biaxial resultants on **concurrent rows only**: `Mu = √(M2² + M3²)`, `Vu = √(V2² + V3²)`,
  `Tu = |T|`, `Pu = P` (CSiBridge P is tension-positive, which is the app's convention).
- Torsion included through the existing `do_torsion`.
- Seismic: Mp from M-φ, Mo = λmo·Mp (λmo user input, default 1.2), Vo from Mo with the selected
  end condition, applied at the top of the shaft; shaft moment and shear demand along its length.
- Shaft moment and shear along its depth from a nonlinear p-y analysis: LPile-style strata (Matlock soft clay,
  Welch/Reese stiff clay, API sand, elastic subgrade; su, φ′, ε50, k, γ, water table), embedded length,
  soil-stiffness bounds (default ×2.0 / ×0.5, enveloped).
- Optional slenderness: Kℓu/r screen and moment magnification. When it is on, the magnified moments replace Mu in the
  strength rows.
- Required reinforcement = envelope of the LRFD strength design, the seismic requirements and the
  user override.

**Non-goals (v1)**
- Displacement demand and capacity, ductility demand, balanced stiffness, column silos. These stay in the
  seismic app; the engineer enters μD and the override reinforcement here instead. (The p-y analysis **is** in
  scope, but only to get the shaft's in-ground forces and the equivalent fixity depth.)
- A refined second-order (P-Δ) analysis. Slenderness uses the approximate method only, and only for
  Kℓu/r < 100 (§5.6.4.1); at or above 100 the bent reports "refined analysis required".
- Rectangular, I-section or box members. Prestressing in the column or shaft.
- Service-limit crack control from separate service cases (see §6, open decision S4).

**Anti-goals (it fails even if it "works" if…)**
- …any existing tab, input, result or saved project behaves differently. `tests/test_rect_i_unchanged.py`
  and the circular tests must stay green, and old project files must load unchanged.
- …it treats CSiBridge `Max`/`Min` envelope rows as if they were concurrent. They are not: the Max row's P, V2,
  M2 and M3 each come from a different step. They go through the **envelope-bounding** rule of §4.1a instead, and
  the results are labelled that way.
- …it uses a code citation that has not been verified (CLAUDE.md rule). Seismic provisions carried over from the
  seismic app keep that app's references and are added to `OPEN_VERIFICATION_ITEMS.md` until they are
  checked against `Seismic Column/AASHTO Seismic 3rd Edn.pdf`.

## 4. How it works (decided)

### 4.1 Import
- Required columns (case-insensitive): `Frame, Station, OutputCase, P, V2, V3, T, M2, M3`.
  `CaseType, StepType, FrameElem, ElemStation` are optional.
- The units row is detected when its `P` cell is non-numeric (e.g. `Kip`, `KN`, `lb`). Supported
  force units: kip, lb, kN, N, tonf. Moment units: kip-in, kip-ft, lb-in, lb-ft, kN-m, N-m, N-mm,
  tonf-m. Length: in, ft, m, mm. Without a units row the tab's unit dropdowns are used
  (default kip / kip-ft / ft).
- Real sample (user screenshot, 2026-10-18): the columns are `Frame | Station | OutputCase | CaseType | StepType | P |
  V2 | V3 | T | M2 | M3 | FrameElem | ElemStation`, the units row is `Text | ft | | Text | Text | Kip | Kip | Kip |
  Kip-ft | Kip-ft | Kip-ft | Text | `, and P is negative in compression. Each frame (e.g. `1227`) is split into
  sub-elements (`1227-1`, `1227-2`), so interior stations appear twice with identical values. These are de-duplicated on
  (Frame, Station, OutputCase, StepType). A header cell that carries its unit on the same line (`Station ft`) is
  also accepted.
- `StepType ∈ {Max, Min}` → `envelope=True`. `StepType` empty or `Step N` → concurrent.

### 4.1a Envelope mode (Max/Min output, for quick runs)
The user's sample (2026-10-18) is an **envelope**. Concurrent output will be added when the user provides an example;
envelope mode stays as the quick option. Notation: CSiBridge P is tension-positive, so **P_max = the least
compression (or most tension)** and **P_min = the most compression**. Per (frame, station, case), with
M = √(max(|M2max|,|M2min|)² + max(|M3max|,|M3min|)²), V = √(max|V2|² + max|V3|²) and T = max(|Tmax|,|Tmin|), where
each absolute maximum is taken over the Max and Min rows:

| Check | Axial used | Why |
|---|---|---|
| Shear (Methods 1–3 / B5), torsion, longitudinal steel for V+T (Eq. 5.7.3.5 / 5.7.3.6.3-1) | **P_max** (least compression) | In `do_shear`, εs = (Mu/dv + 0.5·Nu + …)/(EsAs + …) with Nu tension-positive (`calc_engine.py:2490`), so less compression gives larger εs, lower β and Vc, and a larger longitudinal demand `0.5·Nu/φ` (`calc_engine.py:2712`). The M4 crack-face doubling is triggered by tension. P_max is therefore the conservative value for every shear-side quantity. |
| Flexure (P-M) | **P\* = the P in [P_min, P_max] where the candidate's φMn is lowest** | Mr(P) is not monotonic: below the balance point less compression is worse, above it more compression is worse. For each trial cage, P\* is taken as the lower of the curve values at both ends and at every P-M vertex inside the range. The design curve is piecewise linear, so this is the exact minimum, without relying on a concavity assumption. Pu outside the curve's range → NG. |
| Slenderness δ (when on) | **P_min** (most compression) | δ rises with Pu/Pe. |
| Seismic Mp → Mo | max Mp over P sampled across [P_min, P_max] of the `Extreme` cases plus P_dead (5 evenly spaced + P_dead) | Mp(P) peaks near balance, which can lie inside the range, so the ends alone could miss the maximum overstrength. |
| Seismic shear Vc (column and shaft) | **P_max** of the `Extreme` cases (vc = 0 in net tension, per the ported model) | Vc rises with compression. |

Every station therefore gives **one row** (P_max, M, V, T; checks: all) plus the cage-dependent flexure-only row at P\*,
which is dropped when P\* = P_max. The biaxial combination of envelope maxima is conservative by up to √2 on M and V,
and the report states this.

**Speed.** (1) Rows dominated by another row of the same frame (no better on every one of P_max, M, V, T, and with its
[P_min, P_max] range contained in the other's) are pruned before the search. (2) An optional **member mode** collapses
all stations and cases of a member into one envelope row: the fastest and most conservative setting, meant for sizing.
`envelope_mode ∈ {"station" (default), "member"}`. All rows are tagged `"bound": "envelope"` and labelled
"envelope-bounded (conservative)" in the results and report. Concurrent rows, once supported, are used as they are.

### 4.2 Organisation
- **Bent table** (one row per bent): bent name, column frame IDs, shaft frame IDs (optional),
  column clear height H (default = station span of the column frames), end condition per direction
  (`fixed-free` → Vo = Mo/H, `fixed-fixed` → Vo = 2·Mo/H; the governing direction is used),
  column D, shaft Ds, materials, cover, μD.
- **Load-case table** (one row per distinct OutputCase): category ∈ `Strength | Extreme | Dead | Ignore`.
  Default by name: contains `STR` → Strength, `EQ`/`EXT`/`SEIS` → Extreme, `DEAD`/`DC` → Dead,
  everything else Strength. The user edits these.

### 4.3 LRFD strength design (existing engine)
- Demand rows = every concurrent `Strength` row of the bent's column frames →
  `{Pu, Mu, Vu, Tu, Vp:0, Ms:0, Ps:0}`, as the circular engine expects.
- **Longitudinal search** (Python port of `optimizeFlexureCirc`, `index.html:3682`): bundles 1→3, bar
  sizes #5…#18 within user min/max, n ≥ 6 (§5.6.4.2, already verified C12), clear spacing ≥
  max(user min, 1.5·d_eq, 1.5·ag). Bisect for the fewest bars with flexStatus ≠ NG on every row
  (P-M curve built once per candidate, rows checked with `get_mr_at_pu`). Within 5 % of the least As,
  prefer fewer bars. ρl floor/ceiling from the selected seismic provisions.
- **Transverse search** (port of `optimizeShearCirc`): hoop/spiral bar smallest first, tie legs fewest
  first, pitch largest first. Pass = `shearStatus ∈ {OK, NR}` and `Tr ≥ |Tu|` where torsion must be
  considered, on every row (via `compute_row_capacities_circ`).

### 4.4 Seismic capacity design (ported)
- Section for M-φ = the **governing cage** (§4.5) with expected properties (f'ce = fce_factor·f'c, fye,
  fue, fyh from the provisions).
- Axial loads for M-φ: P_dead (sum of `Dead` rows at the column base, which is auto-detected as the more compressive end, or a user value), plus 5
  evenly spaced values across [P_min, P_max] of the `Extreme` rows at the base. **Mo = λmo · max Mp over those axial loads**,
  reporting the governing P (see §4.1a: Mp peaks near balance).
- Vo = Mo/H or 2·Mo/H per §4.2.
- Column seismic shear: ported `shear_breakdown` (code switch `SDC_2_0`/`AASHTO_SGS`, μD input,
  inside the hinge). It sets the required transverse steel in the hinge zone, together with the ported
  minimum ρs and the detailing-spacing rules.
- Shaft demand, `shaft_basis` ∈:
  - `soil` (**default when strata are entered**): the ported `solve_lateral` on column + shaft with p-y
    springs, loaded so the column develops Mo at the top of shaft. Fixed-free: `V_head = Mo/H`, `M_head = 0`.
    Fixed-fixed: `V_head = 2Mo/H`, `M_head = +Mo` in the solver's DOF sign convention (upstream caller sdc_capacity.py:794 and test_two_direction.py:140; the upstream docstring saying −Mp is stale). The interface then sits at Mo, not 2Mo or 3Mo.
    EI_col = Mp/φy of the column and EI_shaft = Mp/φy of the shaft (both from M-φ). Run on each soil bound and enveloped
    (upstream `inground_demand`). Outputs: M(z), V(z), y(z), the max in-ground M and V with their depths, Df_eq.
    An unstable or non-converged solve is reported as NG ("soil too soft / shaft too short"), never as
    credit.
  - `cantilever` (**the default and required when no strata are entered**, per the user 2026-10-18): the user enters
    the pile's **equivalent cantilever length** `L_eq` below the top of shaft. `M(z) = Mo + Vo·z` and `V(z) = Vo` for
    z = 0…L_eq. The same `L_eq` sets the fixity depth used for ℓu in §4.4b.
  - `interface`: `z = 0` only (kept as an explicit choice for comparison; never the default).
  Shaft flexure demand = `shaft_demand_factor · max M(z)`; shaft shear demand = max V(z) (≥ Vo).
- Shaft capacities: flexure = Mp of the shaft cage from M-φ at P_dead (expected properties); shear =
  ported `shear_capacity(shaft, …, inside_hinge=False)` ≥ Vo. Oversized-shaft confinement
  ρs,shaft ≥ fraction·ρs,col. Minimum oversize Ds − D. If shaft frames are pasted, the shaft is
  also run through the LRFD strength design of §4.3 for its own Strength rows.

### 4.4a Shaft under strength loads (no shaft frames pasted)
When a bent has strata but no shaft frames, the same p-y solve also gives the shaft's LRFD strength
demand. Each Strength row's column-base (Pu, M, V) is applied as `V_head = V`, `M_head = M − V·H`, so
the interface carries exactly (M, V). The in-ground M(z) and V(z) maxima become shaft demand rows for the
§4.3 search. To bound the cost, only the governing rows are solved: the top 5 by base M plus the top 5 by base V
per bent (Claude's call). EI comes from the M-φ of the current cages at that row's axial load.

### 4.4b Slenderness and moment magnification (optional, toggle `slenderness_on`, default off)
Verified from the Chapter 5 text (10th Ed.):
- §5.6.4.1: the approximate procedure applies to nonprestressed columns with Kℓu/r < 100. K is per Art. 4.6.2.5.
- §5.6.4.3: unbraced → slenderness may be neglected if Kℓu/r < 22. Braced → if Kℓu/r < 34 − 12(M1/M2),
  where M1/M2 is positive for single curvature and negative for double curvature.
- C5.6.4.3: circular `r = 0.25·D`. Braced K = 1.0 unless analysis shows lower; unbraced K ≥ 1.0. Mc per
  Art. 4.5.3.2.2b. EI for Pe (Eq. 4.5.3.2.2b-5) = the larger of the two §5.6.4.3 expressions in Ec, Ig, Es, Is and βd.

**Not in our text (blocker — open item S6):** the two §5.6.4.3 EI equations (images) and every equation of
Art. 4.5.3.2.2b (δb, δs, Cm, Pe, the φK factor and ΣPu/ΣPe). The magnification code is written against
**user-supplied** equations only. Until they are supplied, the toggle runs the Kℓu/r screen and reports
"magnification pending verification" with no magnified numbers.

The CSiBridge analysis is linear (user, 2026-10-18), so magnification applies and no P-Δ flag is needed.
Classification per axis: Kℓu/r below the §5.6.4.3 limit → neglect (δ = 1); from the limit up to 100 → magnify;
100 or more → "refined analysis required".

Inputs per bent and direction (the two CSiBridge axes, 2 and 3): braced yes/no, K, ℓu (default `H + Df`, where Df
= the p-y `Df_eq` when strata exist, else the user's `L_eq`; user decision 2026-10-18; editable), βd (default: computed from the `Dead` case moments ×
a user γp, editable). M1/M2 per load case comes from the column frame's end-station moments of the same case and
step. With envelope-only output, M1/M2 cannot be taken from one step. The rule then uses the conservative value
M1/M2 = +1 (single curvature), which gives the lowest braced limit (22) and the largest braced Cm; this is shown in the report.
Envelope mode uses Pu = P_min (most compression) for δ (§4.1a).
Magnification is per axis (M2 and M3 separately), and the resultant is taken afterwards. EI depends on Is, so the LRFD search
magnifies each **candidate's** rows with that candidate's Is (exact, cheap).

### 4.5 Governing cage and override
`final = override if set else max(LRFD, seismic)`. Longitudinal is compared on Ast; transverse on
ρs at equal bar size. The user can override the longitudinal ring (bar, n, bundle) and/or the
transverse (bar, pitch, ties) per bent, separately for column and shaft. With an override, every check
is **re-run on the override cage** and reported pass/fail. The override is never silently "improved".

### 4.6 UI and persistence
- One new tab button **appended** to `#tabBar`, plus one new `tab-panel`. All of its JS lives in
  `colshaft.js`, loaded by a single `<script>` tag. That module may only touch its own DOM ids
  (prefix `cs-`) and its own state.
- Sub-areas: Paste box and parse summary → Load-case table → Bent table → Soil profiles (named strata
  tables, LPile-style; each bent picks one and gives its embedded length) → Slenderness panel (toggle + per-bent
  K/braced/ℓu/βd) → Run → Results grid (one
  row per bent: LRFD cage, seismic cage, override, final, Mp, Mo, Vo, D/C lights) → Bent drill-down
  (governing rows, M-φ plot, shaft M(z)) → Printable report.
- Project file: a new top-level key `columnShaft` (raw paste text, case table, bent table, overrides,
  settings). `version` stays 1. A missing key means an empty tab, so old files load unchanged.

## 7. Later phase (not in this plan)
**Direct read from CSiBridge.** Results live in CSiBridge's binary analysis files, so they cannot be parsed directly. The supported route
is CSiBridge's API (OAPI, a .NET assembly) with the model open: select the frames and combinations and read the frame forces, including
step-by-step values. The app already ships `pythonnet` (the pywebview backend), so no new dependency is needed. It needs
CSiBridge installed on the same PC and an attach-to-running-instance flow. That is moderate work, deferred at the user's suggestion.
The paste parser stays as the always-available path.
